# 更新窗口 Fluent 风格重设计方案

> 范围：`src/views/upgrade.vue` 及其所在的 `upgrade` 窗口（`src-tauri/src/tray.rs`）
> 关联原型：`design/upgrade-redesign.html`（六个状态，`?theme=dark` 深链）
> 视觉基准：`design/preview-ui-design.md`、`design/settings-ui-design.md`（同一套 Fluent 语言）
> **颜色与字号基准：`design/fluent-baseline.md`**（本稿所有色值、字号以该文件为准）
> 版本基线：v1.0.0
> 实现状态：已按本方案落地（`src/views/upgrade.vue`、`src-tauri/src/tray.rs`）
> 入口有两个：托盘菜单「检查更新」（先预检，无更新时弹系统提示）与设置页「关于 → 检查更新」
> （直接开窗，结果交给窗口呈现）。窗口的标题、尺寸与窗口类名由 `tray::open_upgrade_window` 一处给出。
>
> **本文是设计方案，不含实现代码；实现以 `src/views/upgrade.vue` 为准。**

## 1. 背景与目标

设置窗口与预览窗口都已在 v1.1.0–v1.2.0 收敛到 Fluent 2：语义化前景/背景 token、字号阶梯、控件尺寸三档、图标来源唯一。升级窗口是**唯一没有设计稿的窗口**——它由单文件直接写成，从未进入体系，于是留下了四类不属于 Fluent 2 的形态：

1. 「灰底 + 白卡片」的网页分层，窗口四周还留 16px 边距；
2. Element Plus 的加载遮罩（`v-loading`）、进度条（`el-progress`）与按钮（`el-button`），三者的视觉语言都与项目其余部分不同；
3. 品牌浅底 + 3px 品牌条 + 品牌色大字的版本信息条，**恰好违反了基准 §2.3 明令禁止的「accent-soft 上放 brand-fg」**（实测仅 4.07:1）；
4. 更新说明直接套用 `md-viewer` 的**阅读器排版**（h3 20px、列表上下各 16px、行高 1.75），600px 宽的对话框里两条变更就撑满整屏。

目标不是换色，而是让这个窗口在形态上属于同一个应用：

1. 按 Fluent 2 的 **ContentDialog** 组织：标题区 / 内容区 / 页脚三段，同处一整块 surface；
2. 五个状态（检查中 / 已是最新 / 检查失败 / 有更新 / 下载中·完成）各有明确的排版，**无内容的三态整块居中**，且**并列状态的图标成对同尺寸**；
3. 更新说明另按 **UI 正文**（Body1 14/1.43）排版，与阅读视图的 760px 阅读列分开；
4. 窗口尺寸由 600×500 调整为 **640×600**，让 changelog 与进度块不必互相挤占。

## 2. 现状诊断

| 项 | 旧实现 | 问题 |
| --- | --- | --- |
| 容器 | `--color-bg` 页 + `--radius-xl` 卡片 + 内嵌 `notes-wrapper` / `progress-block` 两个浅底块 | 三层嵌套；600×500 的窗口里 16px 页边 + 24px 卡片内边距 = 40px 双重留白 |
| 加载 | `v-loading` 全窗遮罩 + 旋转环 + 居中文字 | Element 的遮罩是「页面被挡住」，Fluent 的 ProgressRing 是内联的；且遮罩会让内容闪一下 |
| 进度 | `el-progress` 14px 条纹 + 条内百分比 | Fluent 2 的 ProgressBar 是 4px 细条、无条纹动画、百分比在条外 |
| 版本信息 | `--color-accent-soft` 底 + 3px 品牌左边条 + 20px `--color-brand-fg` 版本号 | 违反基准 §2.3：brand-fg on accent-soft = 4.07:1；且「浅底 + 指示条」是导航选中态的语言，不是信息展示的 |
| 状态图标 | 错态 56px Element 三角警告 / 成功态 32px 对勾 | 一对并列状态一大一小 |
| 更新说明 | `md-viewer` 阅读排版 | h3 20px、列表 margin 16px、行高 1.75 —— 是 760px 阅读列的参数 |
| 按钮 | `el-button` 重皮 + `:icon` 传 Fluent 图标 | Element 的 icon 走 `el-icon` 包裹，尺寸与间距要二次覆盖；页脚一个有图标一个没有 |
| 标题 | 卡片内 `<h2>` 20px + 标题下 1px 通栏分隔线 | 与系统窗口标题重复；分隔线把标题区割裂 |

## 3. 设计原则

1. **对话框不是页面**。整窗 surface，不铺灰底、不套卡片——Windows 的原生对话框客户区就是一整块 surface，灰的标题栏由 OS 绘制。
2. **用排版分层，不用色块分层**。版本号、发布日期用键值表（`dl`）表达，靠字号与字重区分，不靠浅色底 + 指示条。
3. **状态色只作前景**。成功/失败色只出现在 32px 图标上，不铺彩色底块、不加彩色投影。
4. **内容按用途排版**。changelog 是清单而非长文，走 UI 正文；阅读视图的 760px 排版不进入对话框。
5. **不留 Element 资产**。`el-button` / `el-progress` / `v-loading` 全部退出这一页，改用原生 `button` + token 自绘，避免每个组件都要二次重皮。

## 4. 结构

### 4.1 三段式

```
┌──────────────────────────────────────────┐
│ 软件更新                          v1.0.0 │  标题区：20/28 · 600，版本 chip 右对齐
│                                          │  padding 24 / 24 / 12
│  最新版本    v1.4.0                       │  内容区：可滚动（唯一滚动容器）
│  发布日期    2026年11月6日 09:30          │  padding 0 24 24
│  ──────────────────────────────────────  │  发丝线：更新说明分区
│  新增                                     │
│  • …                                     │
│  ──────────────────────────────────────  │  发丝线：进度分区（贴底）
│  正在下载更新…                      42%   │
│  ▬▬▬▬▬▬▬▬▬▬▬                             │
│  8.6 MB / 20.4 MB · 2.4 MB/s             │
│  ──────────────────────────────────────  │  发丝线：页脚
│                    [重新检查] [立即更新]  │  padding 12 / 24
└──────────────────────────────────────────┘
```

- 根节点即窗口：`height: 100vh`、`background: var(--color-surface)`、`overflow: hidden`。
- 圆角与描边由系统窗口绘制，页面内不再画。
- **只有内容区滚动**，标题区与页脚固定；内容超出时整块滚，不做嵌套滚动区。

### 4.2 两条分隔线的语义

都用 `--color-divider`（发丝线），不用 `--color-border`：

| 位置 | 作用 |
| --- | --- |
| 更新说明区顶部 | 把「版本元信息」与「变更列表」分开 |
| 进度块顶部 | 把「已读内容」与「正在发生的下载」分开 |

页脚顶部也有一条同色线。三条线都不该割裂画面，所以取 NeutralStroke3 而非 NeutralStroke2。

### 4.3 尺寸

| 项 | 值 | 说明 |
| --- | --- | --- |
| 窗口 | 640×600 | 原 600×500。600 宽时正文列 552px，中文长句频繁折行；500 高放不下带进度块的 changelog |
| 标题区 padding | 24 / 24 / 12 | Fluent Dialog 的标题区上边距 |
| 内容区 padding | 0 / 24 / 24 | 与标题区左右对齐 |
| 页脚 padding | 12 / 24 | 上下各 12，按钮 32 高 |

## 5. 逐状态规格

五个状态共用标题区与页脚框架，内容区不同。

### 5.0 状态块排布

**无内容的三态——检查中 / 已是最新 / 检查失败——整块居中**：图标（或进度环）、标题、说明逐段水平居中，整块在内容区垂直居中。

这三种状态总共只有一到两行字，而内容区有近 400px 高。若仍按左上起排，右侧与下方会各留一大片空白，画面重心整个塌向左上角，读者第一眼看到的是空白而不是结论。居中之后，视线落在正中那一个图标与一句话上，「这一屏只有一个结论」这件事才被直接读出来。

「有可用更新」与「下载中 / 完成」是**内容态**（键值表 + changelog + 进度块），仍按 5.4 / 5.5 从左上起排——它们有明确的行序，居中会破坏阅读起点。

**居中不等于拉通栏**：说明文字限宽 `min(100%, 420px)`，超出居中折行。失败态的错误详情常是 URL + 堆栈，一行铺满 592px 需要来回甩头。

### 5.1 检查中

```
        [环]                     ← 20px 环，居中
  正在检查更新…                  ← 14/400 secondary，居中
```

- 环在上、文字在下，间距 8：这一态只有一行字，横排会让「环 + 文字」变成一个窄条飘在正中，竖排更稳。
- 环：20px 外径、2px 笔画、单边高亮；静息段是 `--color-brand-fg` 的 30%（`color-mix`），用 `--color-border` 会在 surface 上淡到看不见。
- 转一圈 0.9s 匀速。`prefers-reduced-motion` 下**放慢到 2.4s 而不是停止**——静止的环会被误读成卡住。
- `role="status"` + `aria-live="polite"`，根节点 `aria-busy="true"`。
- 页脚隐藏（此时没有可执行的操作）。

### 5.2 已是最新

```
              [✓ 32]                   ← --color-success-fg，只染图标，居中
      当前已经是最新版本                ← 16/22 · 600 primary，居中
             v1.0.0                   ← 14/400 secondary，居中
```

图标、标题、版本号三段均居中，整块垂直居中于内容区。

页脚：单个次级按钮「再次检查」。

### 5.3 检查失败

```
              [✕ 32]                   ← --color-danger-fg
           检查更新失败                 ← 16/22 · 600 primary
  failed to fetch release metadata:    ← 14/400 secondary，限宽 420px
  error sending request for url …       居中折行，overflow-wrap: anywhere
```

- **同样居中**：与「已是最新」是一对并列结果，一个居中一个靠左会让人以为两种结局的份量不同。
- 但**说明文字限宽 420px**（`min(100%, 420px)`）：错误详情常是 URL + 堆栈，若一行铺满 592px，换行后视线要从行尾跨过半个窗口才回到行首。限宽后单行不超过约 30 个汉字。
- 页脚：单个主按钮「重试」。

### 5.4 有可用更新

```
最新版本    v1.4.0               ← dt 14/400 secondary（列宽 max-content）｜ dd 16/22 · 600 primary
发布日期    2026年11月6日 09:30   ← dt 同上｜ dd 14/400 primary
────────────────────────────
新增                             ← 14/20 · 600 primary
• PDF 预览支持连续滚动…
```

- 版本号是这一页唯一的强调点，用 16/600 + `tabular-nums`；日期不加粗。
- **标签列宽度由内容撑开，不写死**。`dl` 用 `display: grid; grid-template-columns: max-content 1fr`，行 wrapper 用 `display: contents` 让 `dt` / `dd` 直接落进同一网格。理由：定宽 72px 只在中文下成立（4 字 ≈ 56px），英文 `Latest version` 需要约 95px，加上 `flex: none` 不让撑开，标签会折成两行、值列被挤到右侧错位。`dt` 另加 `white-space: nowrap` —— 标签是一个词，任何语言下都不该断行。
- **不加「更新内容」标签**：release body 自己就带这一级标题（`## 更新内容` / `## What's new`），外面再套一层等于同一句话说两遍。分区交给上面那条发丝线。
- 页脚：`[重新检查]`（次级）+ `[立即更新]`（主，最右）。

### 5.5 下载中 / 下载完成

```
────────────────────────────
正在下载更新…              42%   ← 14/600 primary ｜ 12/400 secondary tabular-nums
▬▬▬▬▬▬▬▬▬▬▬                      ← 4px 轨道，--color-accent；完成态 --color-success-fg
8.6 MB / 20.4 MB · 2.4 MB/s     ← 12/16 tertiary
```

- 进度块 `margin-top: auto` 贴住页脚：进度是「正在发生的事」，不该悬在内容中间。说明区短时剩余留白落在两者之间，被进度块上方的发丝线干净切开。
- 进度条 4px 高、`--radius-xs` 圆角、无条纹与流动动画；`role="progressbar"` + `aria-valuenow/min/max`。
- 页脚：下载中为 `[取消下载]`（次级）；完成后为 `[重新检查]` + `[下载完成]`（主按钮禁用）。

## 6. 更新说明的排版（`.vp-doc` 覆盖）

`md-viewer` 的输出是给预览窗口的 760px 阅读列设计的，参数不能直接复用：

| 属性 | 阅读视图 | 对话框内 |
| --- | --- | --- |
| 正文 | `--md-fs` 15px / `--line-reading` 1.75 | 14px / `--line-base` 1.43 |
| h1–h6 | 1.7em / 1.16em / 20px … | 统一 14/20 · 600 |
| 标题 margin | h3 `32px 0 0` | `12px 0 4px` |
| 列表 | `margin: 16px 0`，`li + li: 8px` | `margin: 4px 0`，`li + li: 2px` |
| 行内代码 | 继承正文 | 12px + `--color-chip-bg` |

覆盖写在 `.uq-notes-body :deep(.vp-doc)` 内，只影响这一页，不改 `md-viewer` 本身——预览窗口仍然需要阅读排版。

## 7. 控件规格

| 控件 | 尺寸 | 状态 |
| --- | --- | --- |
| 版本 chip | 高 `--control-sm` 24，padding 0 8，`--radius-sm`，chip 底 | 静态 |
| 页脚按钮 | 高 `--control-md` 32，padding 0 16，`--radius-sm` | rest / hover / pressed / focus / disabled 五态 |
| 次级按钮 | 透明底 + `1px solid --color-stroke-control` | hover：`--elevation-hover` + 描边转 `--color-text-tertiary` |
| 主按钮 | `--btn-primary-bg` 实底 + 白字 | hover `--btn-primary-hover-bg`，pressed `--btn-primary-active-bg` |
| 进度轨道 | 4px 高，`--radius-xs`，`--color-chip-bg` 底 | 条内不做文字 |
| 状态图标 | 32px（`--icon-xl`），成对同尺寸 | 成功 `--color-success-fg` / 失败 `--color-danger-fg` |

**页脚按钮不带图标**。Fluent 2 的 Dialog footer 就是纯文字；混入图标会把「次级 / 主级」两级在视觉重量上拉平，也会让「重新检查」与「再次检查」两个同义动作看起来不同。

### 7.1 新增 token

`--color-stroke-control`（NeutralStroke1，浅 `#d1d1d1` / 深 `#666666`）：描边的标准按钮需要比 `--color-border`（NeutralStroke2）深一档，否则在 surface 上几乎看不出形状。

## 8. 主题与对比度

全部走既有 token，无新增色值（除上面一个描边档）。关键组合：

| 组合 | 浅色 | 深色 |
| --- | --- | --- |
| 标题 primary on surface | 17.40:1 | 14.16:1 |
| 键值标签 secondary on surface | 7.46:1 | 8.82:1 |
| 进度明细 tertiary on surface | 6.19:1 | 6.31:1 |
| 失败图标 danger-fg on surface | 7.88:1 | 6.97:1 |
| 成功图标 success-fg on surface | 6.28:1 | 5.20:1 |
| 主按钮白字 on accent | 4.53:1 | 4.53:1 |

深色下 `--btn-primary-disabled-text` 由 `#555555` 提亮为 `#999999`：`#555` 压在 `#333` 上只有 1.9:1，禁用态虽豁免 WCAG，也不该看不见。

## 9. 实现要点

1. **一个滚动容器**：只有 `.uq-main` 有 `overflow-y: auto`，`.uq-notes-body` 不滚动。500–600px 的窗口里嵌套滚动区会让滚轮滚错层。
2. **说明区不撑满**：`flex: 0 1 auto`。若撑满，短 changelog 会在分隔线下方留下大片空区，被读成「列表没加载出来」。
3. **进度块贴底**：`margin-top: auto`，让空白落在进度块上方而非页脚上方。
4. **进度环自绘**：CSS `border` + 单边高亮，不取自 `@vicons`——图标库里没有可旋转的进度环，它也不属于图标。
5. **窗口尺寸**：`src-tauri/src/tray.rs` 的 `inner_size(640.0, 600.0)`。

## 11. 明确不做

- **不改下载与安装逻辑**。本稿只处理视觉与排版，`downloadAndInstall` 的事件流、取消后重检查、速度采样都保持原样。
- **不加「立即重启」**。下载完成后的下一步（重启生效或退出时安装）属功能变更，需要先定产品语义；当前仍以禁用主按钮 + 「下载完成」表示。
- **不合并「重新检查」与「再次检查」两个文案**。它们是既有 i18n 资产（`upgrade.recheck` / `upgrade.checkAgain`），合并会牵动两份语言文件与调用点，收益不抵风险。

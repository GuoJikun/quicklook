# 预览类型 UI 统一设计方案

> 范围：除音频（已按 `design/audio-preview-design.md` 重构）与视频（xgplayer 宿主页）之外的 9 种预览类型
> 关联原型：`design/preview-types-redesign.html`（9 种类型可切换，含浅色/深色，支持 `?theme=dark#archive` 深链）
> **颜色与字号基准：`design/fluent-baseline.md`**（本稿所有色值、字号以该文件为准）
> 目标文件：`src/components/layout-preview.vue`、`src/views/preview/{image,md,code,document,book,archive,font,model,not-support}.vue`
> 本文只做设计，不含实现代码

## 1. 背景与目标

`src/views/preview/` 下现有 11 个视图，其中音频已完成沉浸式重构（560×360 固定单态），视频使用第三方播放器自带控件，**其余 9 种仍是长期各自演进的结果**，缺少统一的视觉与交互契约。

目标：在不推翻各类型既有能力的前提下，建立一套可复用的预览外壳，使 9 种类型在**标题层级、命令栏位置、滚动行为、空/错状态、元信息呈现**上表现一致。

## 2. 现状诊断

| 类型 | 视图规模 | 现有 chrome | 主要问题 |
| --- | --- | --- | --- |
| 图片 | 69 行 + `preview-image.vue` | Header/Footer + 组件内控件 | 缩放/旋转控件由组件自绘，与全局无共享；仅在真全屏时隐藏头尾 |
| Markdown | `md.vue` + `md-viewer/` | Header/Footer | 无目录、无字号、无源码切换；错误态是两行裸文本 |
| 代码 | 112 行 | Header/Footer | 无行号、无语言标识、无换行开关、无复制；内容区居中导致长行浪费 |
| 文档 | `document.vue` + 3 个子视图 | 无命令栏 | PDF/DOCX/Excel 三套完全独立的交互，无页码、无缩放、无目录 |
| 书籍 | 25360 字节 | **自带 toolbar** + 侧栏 | 标题在 header 与 toolbar 重复出现；字号控件与全局框架割裂 |
| 压缩包 | 163 行 | Header/Footer | `el-tree` 三列无表头、无搜索、无排序、无总数统计 |
| 字体 | 96 行 | Header/Footer | 单一预览块，无字号阶梯、无自定义文本、无明暗底切换 |
| 3D 模型 | 20453 字节 | Header/Footer + 浮层 | 相对完整，但控件为裸 SVG、无 tooltip 体系、加载无进度 |
| 不支持 | 28 行 | Header/Footer | 仅一行居中文字，看不出格式与体积；可用的打开入口只有标题行的小图标 |

两处共性问题，来自代码而非观感：

1. **缺少「内容命令栏」这一层**。`book.vue` 为了放字号和目录，自行造了一条 toolbar；`model.vue` 造了一组浮动按钮；`preview-image.vue` 造了组件内控件。三者视觉基准（高度、图标尺寸、hover 底色）各不相同，同一窗口内出现两套按钮是当前最明显的割裂来源。
2. **尺寸体系不干净**。`footer.vue` 用 `zoom: 0.8` 硬缩放文本，`header.vue` 的操作项 `min-width: 4rem` 与 `font-size: 2rem` 依赖 rem 而非既有 `--space-*` / `--font-*` 变量，导致 28px 高的 header 内按钮实际宽度远大于图标本身。

## 3. 设计原则

本方案的视觉语言**直接沿用 `design/audio-preview-redesign.html`**，不另立一套。音频预览已经验证过的六条规则，在这里作为硬约束：

1. **不做条带切割**。窗口只有一种底色（`--color-bg`），标题行与命令栏**背景透明**，不加 `border-bottom`。区域之间靠留白、圆角、阴影区分，不靠 1px 实线或白底横条。
2. **控件悬浮，不占条带**。按钮常态无底色；hover 才浮现 `--elevation-hover`；按下用 `--elevation-pressed`；开关已开启用 `--color-selected-strong`。图标按钮 32×32（`--control-md`）、圆角 `--radius-sm`，图标 16px（`--icon-sm`）。
3. **标题即内容第一层**。文件名 16px/600，紧跟其后是 10px/600 全大写胶囊（格式、大小等，高 `--badge-h` 22），与音频页的 `MP3` / `320k` 完全同规格。
4. **取消状态栏**。原来的 Footer 20px 是「老式分栏」观感的主要来源，元信息改为标题行胶囊承载，不再单独占一条。
5. **一种内容形态，一套层级**：所有类型共用 `标题行 → 命令栏 → 内容` 三层，类型差异只体现在命令栏内容与内容渲染器上。
6. **复用既有设计变量**：颜色只用 `--color-bg / --color-surface / --color-accent / --color-text-primary / --color-text-secondary / --color-border / --elevation-hover`；尺寸只用 `--space-1..6`、`--font-xs..3xl`、`--radius-xs..xl` 与 `--radius-pill`、`--icon-xs..xl`。禁止新增硬编码色值、字面量圆角与 rem 字号。

两类补充规则：

- **沉浸式是一种模式，不是一种类型**：图片全屏、视频播放、音频单窗共用 `immersive` 语义——隐藏标题行与命令栏，内容占满。非沉浸类型不得私自隐藏框架。
- **类型特有操作一律外提**：不在内容区浮动按钮。浮动按钮只在沉浸模式下、且随鼠标出现时才允许存在。

## 4. 统一框架

### 4.1 三层结构

```
┌──────────────────────────────────────────────────────┐
│ 山间晨雾.jpg  [JPG] [4.2 MB]              [···] [✕]  │  标题行 44 · 透明
│                                                      │
│ −  100%  +   │  适应窗口  1:1  │  ↺ ↻ │ ⛶ 全屏       │  命令栏 40 · 透明
│                                                      │
│                                                      │
│                  内容渲染区（唯一滚动容器）             │  内容 1fr
│                                                      │
└──────────────────────────────────────────────────────┘
```

| 区块 | 高度 | 背景 | 说明 |
| --- | --- | --- | --- |
| 标题行 | `--layout-header-h`（**44px**，原 28px） | 透明 | 文件名 16px/600 + 元信息胶囊 + 窗口按钮，右侧按钮区 `margin-left: auto` |
| 命令栏 | `--layout-toolbar-h`（**新增**，44px） | 透明 | 无操作时不渲染，不留空行 |
| 内容 | `1fr` | 透明 | 唯一滚动容器，滚动条统一 8px |

窗口容器本身：`border-radius: var(--radius-xl)`（12px）+ 1px `--win-border`（浅色透明、深色 8% 白）+ 双层阴影，与音频窗口一致。

> **与旧版的差异**：原来是 `Header 28 + Toolbar 28 + Body + Footer 20` 四段式，三条 `--color-surface` 白底横带把窗口切成「上中下三截」，是本次被否掉的核心原因。新版把标题行抬高到 44px（能容纳 16px 标题与胶囊）、命令栏放到 44px（容纳 32px 命中区），并全部改为透明。

### 4.2 命令栏规格

| 项 | 规格 |
| --- | --- |
| 容器 | `height: 44px`，`padding: 0 10px`，**无背景、无边框**，`white-space: nowrap` + `overflow: hidden` |
| 左区 | 类型特有操作，按功能分组，组间用 1px × 16px `--divider`（半透明发丝线）+ 8px 空隙 |
| 左区顺序 | 跨类型统一为 **目录 → 视图方式（预览/源码、适应宽度、旋转）→ 缩放**，其后才是类型独有操作；新类型照此插入，不按「哪个常用放前面」另排 |
| 右区 | 只放「状态类」信息（如 PDF 页码、压缩包统计），12px、`--color-text-secondary`，**裸文本不加胶囊** |
| 按钮 | 命中区 `--control-md` 32×32，视觉图标 `--icon-sm` 16px，圆角 `--radius-sm`，间距 2px |
| 按钮态 | 常态 `--color-text-secondary`；hover `--elevation-hover` + `--color-text-primary`；按下 `--elevation-pressed`；开关已开启 `--color-selected-strong` + `--color-text-primary`（见基准 §2.5） |
| 禁止 | 命令栏内不放主操作（主操作统一为内容区空/错状态里的按钮） |

### 4.2.1 命令栏内的三类特殊控件

命令栏 44px 仍是单行，任何一处折行都会顶破容器并向下溢出到内容区（原型初版出现过「搜索」被压成两行、「A4 · 128 页」被挤出右边界）。因此：

| 控件 | 规格 | 用途 |
| --- | --- | --- |
| 输入框（`tb-input`） | 高 `--control-md` 32px，**1px `--color-border` 描边 + 透明底**，`--radius-sm`，最大宽 340px，单行 + 省略号 | 压缩包过滤、字体样例文本、PDF 搜索 |
| 数值框（`tb-value`） | 高 `--control-sm` 24px，`--chip-bg` 填充底，`tabular-nums`，最小宽 48px | 字号档位、缩放百分比等只读数值 |
| 色板（`swatch`） | 12×12，圆角 `--radius-xs`，1px 描边 | 阅读底色、背景色选择 |

输入框用描边、数值框用填充，二者必须有区别——否则输入框会被误读成只读标签。

实现约束（三条，缺一即出问题）：

1. 命令栏容器 `white-space: nowrap` + `overflow: hidden`；
2. 除 `flex-grow` 占位元素外，所有直接子项 `flex: none`，禁止被压缩；
3. 命令栏内小号图标必须**同时**指定 `width` 与 `height`（只给 `width: 10px` 会被 `16px` 的默认高度拉成长条）；
4. 界面图标一律来自 `@vicons/fluent`，尺寸只取 `--icon-xs/sm/md/lg/xl`（12/16/20/24/32）。手绘描边 `svg` 与 `@element-plus/icons-vue` 都不允许出现在命令栏、标题行与列表里——三者的笔画重量差一档，并排就能看出来。唯一例外是空态/错态的成幅插画（≥40px，笔画按 48 网格取 2px）与「关于」页的应用标识。

### 4.3 新增变量

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--layout-toolbar-h` | 44px | 命令栏高度，与标题行等高 |
| `--divider` | 浅色 `rgba(0,0,0,.07)` / 深色 `rgba(255,255,255,.08)` | 发丝线，替代 1px `--color-border` 做轻分隔 |
| `--preview-scrollbar-w` | 8px | 统一滚动条宽度 |
| `--preview-reading-w` | 760px | 阅读类（Markdown/DOCX）单列最大宽度 |
| `--preview-code-line-h` | 20px | 代码行高基准 |

颜色不在此表新增。品牌强调色按 `design/fluent-baseline.md` §2.1 拆为前景 `--color-brand-fg` 与背景 `--color-accent` 两支：链接、焦点环、选中项的 3px 指示条用 `--color-brand-fg`；命令栏开关按钮的开启态是中性底 + 中性文字（品牌色在 12px 文字上放不进任何候选底，见 `design/fluent-baseline.md` §2.5）；只有实心底（主按钮、进度条、开关轨道）用 `--color-accent`。


### 4.4 空态与错态（统一形态）

所有类型复用同一结构，替代当前各视图的裸文本：

```
        ┌──────────────────┐
        │      [图标 48]     │
        │   标题 16px/600    │
        │  原因 14px/次要色   │
        │  [主按钮] [次按钮]  │
        └──────────────────┘
```

主按钮固定为「用默认程序打开」（调用既有 `openPath`），次按钮按类型给「打开所在文件夹」或「重试」。错误原因必须来自后端返回值，不臆造文案。

## 5. 逐类型规格

### 5.1 图片

```
命令栏  −  100%  +  │ 适应窗口  1:1  │ ↺ ↻ │ ⛶ 全屏        右区：3840 × 2160
Body     居中 contain，非沉浸时内边距 24px
```

| 项 | 规格 |
| --- | --- |
| 缩放显示 | 百分比文本 12px `tabular-nums`，宽度固定 56px 防抖动 |
| 缩放步进 | 按钮 ±25%；滚轮连续（Ctrl 按下时）；范围 10%–800% |
| 适应窗口 | 默认态，窗口尺寸变化时保持；双击内容区在「适应窗口/1:1」间切换 |
| 旋转 | ±90°，仅影响显示不改文件 |
| 全屏 | 归入左侧控件组，与旋转同组；**不要单独放在命令栏最右端**（初版即因此成为孤立图标，视觉上与命令栏脱节） |
| 沉浸 | 进入全屏时隐藏标题行与命令栏；退出还原。**不做**"hover 自动隐藏"（见 §7） |
| 缩放 > 100% | 出现 1px `--color-border` 的视口边框，避免用户误以为图片被裁切 |
| 元信息 | 非沉浸时，hover 底部浮出胶囊：`1920×1080 · 2.4 MB · png`，透明 200ms；命令栏右区只留分辨率作为常驻状态 |

改动要点：把 `preview-image.vue` 内的缩放/旋转/全屏控件外提到 命令栏，组件只保留画布与手势。

### 5.2 Markdown

```
命令栏  ☰ 目录 │ 预览 源码 │ A− A+  ……  1,284 字 │ 复制全文
Body     单列 760px 居中，左右 48px，行距 1.75（--line-reading），正文 15px
```

| 项 | 规格 |
| --- | --- |
| 目录 | 左侧目录栏 220px，**h1/h2/h3 三级**，缩进 0/16/28；当前节由滚动位置高亮 |
| 目录态 | **挤压式**：展开时占 220px 列宽，正文在**剩余区域**内居中，关闭后回归窗口居中（与 PDF 一致）；不做覆盖式——覆盖式在宽窗口下正文按整窗居中，目录压掉左留白一角，正文会相对可见区域偏左；Esc 关闭；开关与字号按类型记忆 |
| 源码切换 | 与预览共用同一滚动位置，避免切换后丢失阅读点 |
| 代码块 | 顶部 24px 语言标签（`--font-xs`）+ 右侧复制按钮，hover 才显示 |
| 表格 | 宽度溢出时横向滚动；表头**不做 sticky**——滚动容器在 `.md-table-wrap` 之内建立包含块，sticky 不会跟随外层滚动 |
| 长文档 | 超过 8 万字时正文改为 `content-visibility: auto` 分块（性能） |

### 5.3 代码

```
命令栏  [Rust] │ 自动换行 ⊞ │ A− A+ │ 复制 │ 外部打开
Body     全宽，左行号列 48px 右对齐，内容 padding 12/16，行高 20px
```

| 项 | 规格 |
| --- | --- |
| 行号 | 独立列，`--color-text-disabled`，不参与文本选中，随内容同步滚动 |
| 自动换行 | 默认关闭（代码横向滚动）；开启后行号列为每逻辑行显示首个行号 |
| 语言标识 | 取自扩展名，胶囊样式与音频页规格一致（`--radius-sm`，`--color-bg` 底） |
| 大文件 | 超过 5000 行降级为纯文本 + 顶部提示条，避免高亮卡顿 |
| 搜索 | P2：`Ctrl+F` 唤起命令栏内联搜索框（左侧展开，替换左区内容） |

### 5.4 文档（PDF / DOCX / Excel）

当前三种子视图完全独立，是本方案改动量最大的一处。统一为同一 命令栏，按钮按类型显隐：

| 子类型 | 命令栏 内容 |
| --- | --- |
| PDF | `☰ 目录` │ 适应宽度 ↻ │ 缩放 − 100% +  ……  `‹ 3 / 128 ›` |
| DOCX | 缩放 − 100% + │ 适应宽度 │ 分页/连续 |
| Excel | Sheet 下拉 │ 冻结首行 │ 公式栏 |

> 左区顺序与 Markdown 一致：**目录 → 视图方式 → 缩放**，右区只放状态。原先把页码放在最左、目录放在最右，切换类型时视线要重新定位，已统一。

| 项 | 规格 |
| --- | --- |
| PDF 内容 | 连续滚动，页间距 12px，页面投影 `0 1px 2px rgba(0,0,0,.08)`，底色 `--color-bg` |
| PDF 缩放 | 100% 为"适应宽度"，超过 150% 时转为横向滚动并保持页面居中；范围 10%–500%，步进 10% |
| PDF 目录 | 复用抽屉规格（220px），h1–h3，层级由后端 outline 提供；**挤压式**——PDF 页面铺满宽度，覆盖式会挡住左侧正文 |
| PDF 搜索 | 待后端文本抽取与坐标映射，命令栏暂不呈现（当前渲染为位图，前端无法本地搜索） |
| DOCX 内容 | 沿用 `docx-preview` 渲染，单列 `--preview-reading-w` 居中，纸张投影同 PDF |
| Excel | 保留 handsontable（已有 `--ht-*` 变量体系），仅收紧表头 24px、行高 24px |
| 页码定位 | 右区 `‹ [3] / 128 ›`，滚动时实时同步，点击页码输入框可跳转 |

### 5.5 书籍（EPUB）

设计重点是**去重**：删掉 `book-toolbar` 中的标题与字号控件，其余能力迁入统一命令栏。

```
命令栏  ☰ 目录 │ A− 16 A+ │ 底色 ■■■  ……  第 3 章 · 全书 42%
Body     单列 680px，行距 1.75（--line-reading），首行缩进 2em；内容底部 3px 横向进度条（左右内缩 16px）
```

| 项 | 规格 |
| --- | --- |
| 命令栏顺序 | 与其余类型一致：目录 → 字号 → 底色，右区只放阅读进度 |
| 目录抽屉 | 240px，h1–h3 缩进 16px/级，当前条目高亮；**始终挤压式**——覆盖式下 680px 正文仍按整个阅读区居中，看上去会偏左压着目录。顶部放书名与作者，替代原 toolbar 里重复的标题 |
| 字号 | 14–24px 六档（默认 16），记忆到 `config.data`（与整体 UI 字号解耦）；当前档位用 `tb-value` 数值框呈现 |
| 底色 | 白纸 / 米黄 / 深色三档，用 28×28 色板按钮（12×12 `swatch`）而非文字标签；**仅作用于阅读区**，首次进入跟随系统主题，用户选过就尊重用户 |
| 进度 | **内容底部 3px 横向进度条**（`--color-accent`，左右各内缩 16px、圆角 `--radius-xs`），不用右缘竖条——竖条与滚动条难以区分，初版已因此改回横向；进度条不要贴到窗口底边，否则会被当成窗口边线；抽屉打开时左端右移 240px，与正文区左缘对齐 |
| 进度算法 | （章序号 + 章内滚动比例）/ 总章数，按 `spine` 序而非 TOC 条目数计算，否则同文件多锚点会把分母撑大 |
| 元信息 | 「第 N 章 · 全书 42%」放命令栏右区；格式与大小进标题行胶囊，不再有 Footer |
| 待实现 | 单页/双页翻页模式、首行缩进开关；跨文档脚注跳转仍走 `resolve_epub_link` |

### 5.6 压缩包

现状 `el-tree` 三列无表头，改为表格式树：

```
命令栏  🔍 过滤  │ 排序：名称 ▾ │ 展开/折叠
```

| 项 | 规格 |
| --- | --- |
| 图标 | 目录 / 文件 / 加密（锁）三态，16px，`--color-text-secondary` |
| 排序 | 名称、大小、时间三选一，目录恒置顶 |

### 5.9 不支持

```
标题行  文件名（如 backup.db）+ [DB] [26.8 MB] 胶囊
Body   居中卡片 420px：文件类型图标 48
       标题「暂不支持预览」16px/600
       副标题「.xyz · 2.4 MB」12px 次要色
```

该类型没有命令栏——不要为了「结构完整」留一条空栏。

卡片内**不放按钮**：打开文件、打开所在文件夹在标题行已经有同样的入口，再摆一遍既是重复，也会把「只说明状态」的页面变成操作面板。
卡片不加重投影，靠 `--color-surface` + `--radius-lg` 与正文区分；宽度撑满再被 `max-width: 420px` 收住，窄窗口下不会顶出可视区。

## 6. 优先级与实施顺序

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| P0 | 统一框架（标题行 + 命令栏组件 + 空/错态）+ 文档类 | 框架是所有类型的前置；文档类是三套割裂 UI，收益最大 |
| P1 | Markdown 目录 + 代码命令栏 | 两类高频、改动局限在各自视图 |
| P2 | 压缩包表格式 + 字体阶梯 + 不支持页 | 独立性强，可并行 |
| P3 | 书籍去重 + 3D 控件统一 | 现状可用，属打磨 |

实施顺序上，P0 必须先落地 `LayoutPreview` 的 命令栏 插槽与 `--layout-toolbar-h`，否则后续每个类型都会重复造一条命令栏，正是当前问题的成因。

## 7. 待确认的三个决策

1. **是否引入 命令栏 层**：会改动 `layout-preview.vue` 与 6 个视图（document/book/archive/font/model/代码类）。替代方案是各视图自绘，但本方案认为那正是现状问题的根源。
2. **图片是否改为「默认沉浸 + chrome 自动隐藏」**：macOS Quick Look 的做法。风险是 Windows 用户不习惯标题栏消失，且拖动窗口的落点变少。本文档 §5.1 采取保守方案（仅在真全屏时隐藏），如需激进版可另出一版。
3. **文档类窗口尺寸**：当前所有非音频类型统一取屏幕 80%。PDF 连续滚动在 80% 屏幕下偏大但可接受；若希望 PDF 与 DOCX 固定为「阅读版式」（如 900×700），需在 `calc_window_size` 增加分支，属于后端改动，需单独确认。

## 8. 风险与取舍

- **命令栏挤占内容高度**：标题行 44 + 命令栏 40 共 84px，比原来的 28+28+20=76px 多 8px。在 1000×600 的预览窗里可接受，但 1366×768 且缩放 150% 时需注意内容最小高度。缓解方式：无操作的类型不渲染命令栏；标题行与命令栏均为透明，视觉压迫感低于等高的白底条带。
- **抽屉与正文的宽度博弈**：覆盖式不压缩正文，代价是正文相对「可见区」偏左——PDF 页面本身铺满宽度（适应宽度），覆盖式会直接吃掉页面左缘，故始终挤压，由 `ResizeObserver` 重算适应比例；书籍目录 240px 始终挤压，封面/正文列都按「扣除目录后的可见区」居中。Markdown 原先只在 ≤1299px 挤压，宽窗下 760px 阅读列按整窗居中、左留白又被 220px 目录吃掉一角，同样偏左，现统一为 220px 分栏挤压。
- **Excel 改造边界**：handsontable 自带 UI 较重，本方案只收窄表头与行高，不重写其工具栏，避免与其内部渲染冲突。
- **PDF 缩放与 DPI**：现有多页渲染已按 DPI 换算，新增缩放控件需与其统一坐标系，否则出现"缩放 100% 但页面偏小"。
- **性能**：Markdown 目录高亮、压缩包过滤、代码高亮均为大文件敏感路径，均需设定阈值降级。

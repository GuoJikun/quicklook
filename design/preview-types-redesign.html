项目架构说明

最后更新于 2026-11-03 · 约 8 分钟阅读

QuickLook 采用 Tauri v2 构建，Rust 侧负责文件解析与系统集成，Vue 3 侧负责渲染。两侧通过 invoke 与事件通道通信，预览窗口在切换文件时复用同一实例。

1. 渲染进程分工

每个预览类型对应一个独立视图，统一挂在 /preview/:type 路由下。视图只关心内容渲染，窗口尺寸、标题栏与元信息由外层布局组件承担。

  • 布局层：标题行、命令栏、加载与错误态
  • 渲染层：按类型分派到具体渲染器
  • 数据层：通过 IPC 拉取解析结果与缩略图

use tauri::{AppHandle, Manager, WebviewUrl};
/// 非音频类型统一取屏幕的 80%，再按 DPI 换算。
fn calc_window_size(file_type: &str) -> (f64, f64) {
let info = monitor::get_monitor_info();
let mut width = info.width * 0.8;
let mut height = info.height * 0.8;
if file_type == "Audio" {
width = 560.0;
height = 360.0;
}
if info.scale > 1.0 {
width = get_scaled_size(width, info.scale);
height = get_scaled_size(height, info.scale);
}
log::info!("Client Rect: {} × {}, scale {}", width, height, info.scale);
(width, height)
}
pub fn preview_file(app: AppHandle) -> Result<(), TauriError> {
let path = Selected::get_selected()?;
let info = get_file_info(&path);
let kind = info.get_file_type().to_string();
let route = WebRoute::get_route(&kind, info);
show_preview(app, route);
Ok(())
}

2026 年度技术规划

预览引擎重构与渲染管线优化 · 草案 v0.3

本年度的工作重心从「覆盖更多格式」转向「统一渲染管线」。当前 11 种预览类型各自实现了分页、缩放与滚动逻辑，重复代码与体验差异同步增长，已成为维护成本的主要来源。

图 1 · 标题行 + 命令栏外壳示意

统一外壳的目标是让类型差异只体现在命令栏内容与内容渲染器上。标题行与命令栏由布局组件统一承担，渲染器不再关心窗口装饰与元信息呈现。

第二阶段聚焦解析侧的延迟。PDF 首屏依赖页面位图渲染，冷启动延迟约 480 ms；通过预渲染首页缩略图与复用页面缓存，目标降至 200 ms 以内。
